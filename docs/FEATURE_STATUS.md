# Canonical feature ledger

This is the source of truth for implementation progress. `IMPLEMENTED` means code and automated tests exist; `VERIFIED` additionally requires bidirectional upstream evidence. `WIP` names missing behavior, `PLANNED` has no complete implementation, and `BLOCKED` records an external dependency.

| LXMF URI and paper-message codecs | IMPLEMENTED | `lxmf_paper_pack/unpack` signs normal LXMF, encrypts `source || signature || payload` with the destination identity or advertised ratchet, prefixes the 16-byte destination, computes the transient SHA-256 ID, and verifies/decrypts with bounded private-ratchet history. `lxmf_uri_encode/decode` implements the pinned canonical `lxm://` URL-safe Base64 form without padding, the 2,210-byte paper/2,953-character QR limits, case-insensitive scheme parsing and bounded slash-separated scanner input. The complete packed message preserves title, stamp and unknown MessagePack fields. Provenance-recorded fixtures produced by pinned LXMF `795fdaa2b0777c13033787d933d1afc94a2377cb` `LXMessage.as_uri(finalise=False)` cover 97-byte, binary 2,048-byte and maximum-size paper data; deterministic crypto/ratchet round trips, malformed/boundary tests and `fuzz_lxmf_uri` exercise the C implementation. The URI prefix is `lxm://`, not `lxmf://`, and there is no separate paper compression layer. Application import/export, QR rendering/scanning and live upstream encrypted-paper exchange remain. Fixture equality and local router tests are not full paper interoperability evidence. |

| Hosted page form decoder | IMPLEMENTED | `rns_hosted_form_decode` validates exactly one bounded MessagePack map without allocation, retains callback-scoped scalar `field_`/`var_` values, skips structurally valid unknown fields, rejects composite retained values and trailing/truncated input, and gives duplicate keys final-value semantics. `test_hosted_form` covers canonical string, binary, Boolean, signed, unsigned, floating and nil scalars, nested ignored data, non-string keys, map16/map32, alias ownership, duplicates and bounds. | Executable hosted Micron pages | BLOCKED | The pinned implementation executes a page path directly. A secure descriptor-pinned equivalent is not portable across the initial POSIX targets: macOS does not expose `fexecve`, and executing `/dev/fd` is unavailable. Falling back to a validated pathname would reintroduce a file-swap race. No executable-page code is retained; this needs an isolated helper/sandbox design with an explicit interpreter policy, deadlines and output caps before implementation. |
