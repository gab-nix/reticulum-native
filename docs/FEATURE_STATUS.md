# Canonical feature ledger

This is the source of truth for implementation progress. `IMPLEMENTED` means code and automated tests exist; `VERIFIED` additionally requires bidirectional upstream evidence. `WIP` names missing behavior, `PLANNED` has no complete implementation, and `BLOCKED` records an external dependency.

| Area | Status | Evidence and remaining work |
| --- | --- | --- |
| C17 build, HAL, buffers, status API | IMPLEMENTED | Warning-as-error builds and unit tests. Embedded adapters remain planned. |
| Crypto, identities, destinations, packets | IMPLEMENTED | Known-answer and unit tests. Identity encryption supports announced X25519 ratchets, ordered private-ratchet decryption, ratchet IDs, identity-key fallback and strict ratchet enforcement. A bounded signed MessagePack ratchet store persists up to the upstream-default 512 private keys, rotates at the upstream-default 30-minute interval, rejects tampering and copies decryption keys newest-first. The runtime can sign the current ratchet into announces. The full upstream vector matrix remains WIP. |
| Signed announces and paths | WIP | Build/parse/verification, verified runtime callbacks and path snapshots tested. Verified events now expose the borrowed public ratchet bytes, and the bounded registry copies the ratchet plus decoded LXMF delivery name, stamp cost and compression capability while retaining original announce app data. Persistent discovery and upstream bidirectional capture remain. |
| UDP and TCP interfaces | IMPLEMENTED | Loopback tests, setup guide and a reachability-checked public uplink configuration. Protocol-level upstream testing remains. |
| AutoInterface, shared IPC, serial KISS, RNode | PLANNED | Framing primitives exist; interface drivers do not. |
| Transport forwarding | WIP | Basic ingress, forwarding and dedupe exist. Local ordinary-packet receipts now validate explicit or implicit identity proofs, report RTT/timeouts/cancellation, and can emit a proof on the receiving interface. Reverse-path forwarding, link/tunnel tables and persistent paths remain. |
| Links and channels | WIP | Handshake crypto, bounded channel state, and caller-polled outbound and inbound runtime link lifecycles exist. Identity-associated inbound destinations validate link requests, return signed LRPROOFs, authenticate RTT confirmation and encrypted packets, and use protocol-correct raw keepalives. Encrypted application packets support explicit ephemeral-key proofs, initiators can privately identify, and active links dispatch single-segment Resource control/data frames. Provenance-recorded pinned Python fixtures validate deterministic link-request/LRPROOF packet bytes, link IDs, proof and identification signing preimages, signatures, signalling, and RTT MessagePack plaintext; deterministic C-to-C UDP tests cover the runtime foundation. Random-IV ciphertext, live Python handshakes, inbound request handlers, backchannel routing and multi-hop reverse paths remain. |
| Resources | WIP | The receive side parses advertisements, requests bounded windows, matches reordered parts by map hash, decompresses bz2, verifies hashes and emits completion proofs. A bounded single-segment sender constructs the pinned 11-field advertisement, optionally compresses, encrypts the complete stream, collision-checks part map hashes, serves requested parts and validates completion proofs. Runtime links expose caller-owned transfer state, bounded application acceptance/completion callbacks, encrypted advertisement/request/cancel/reject control frames, raw parts/proofs, progress, timeout and teardown handling. Deterministic C-to-C core and UDP runtime tests cover success, rejection, cancellation, malformed control frames, timeout and teardown. Transfers remain limited to the 74 parts carried in one advertisement; adaptive retries, hashmap updates, multi-segment transfer, resume and pinned-upstream evidence remain. |
| LXMF codec, signatures, stamps, tickets | WIP | Core codec and unit tests exist. Canonical pack/unpack uses bounded heap workspaces up to 8 MiB instead of the former hidden 4 KiB stack ceiling. Delivery announce parsing retains bounded unknown supported-function identifiers and extension MessagePack objects for lossless re-encoding; registry tests cover verified ratchet and advertised stamp/compression metadata retention. Provenance-recorded fixtures generated by pinned Python LXMF 1.1.0 validate delivery announce data plus exact signed message representations, IDs, signing preimages, UTF-8 title/content, renderer/reply/reaction and unknown fields, the 255-byte binary boundary, and destination-prefix-elided opportunistic payloads. A bounded, versioned, atomic ticket store issues, throttles, retains, expires and validates ticket-backed stamps using the pinned lifecycle constants. The router now parses bounded `FIELD_TICKET` values from verified messages, remembers valid unexpired tickets, and reuses them without dropping unknown fields. Random Reticulum ciphertext and live ticket exchanges remain unverified. |
| LXMF delivery and propagation | WIP | Opportunistic encoding matches the pinned Python layout and uses proof-backed delivery. Verified advertised ratchets are selected for opportunistic encryption, and the local signed history decrypts newest-first with bounded identity-key fallback. The Nomad client defaults to direct delivery: the router registers its authenticated inbound `lxmf.delivery` link destination, reuses active outbound links, sends packet-sized representations with ephemeral-key receipts, and sends larger retained representations through the bounded single-segment Resource runtime. Inbound packet and Resource representations share destination, message-ID, signature and duplicate validation. Router-owned link-packet proofs are returned only after signature, destination and configured stamp-policy acceptance; configured costs accept issued-ticket or proof-of-work stamps. Resource progress, proof hash, cancellation, rejection and timeout are durable; `SENT` is recorded only once transfer completion is proven, and the pinned direct-Resource COMPLETE callback maps to `DELIVERED`. C-to-C UDP tests exercise packet and Resource paths, exact retained bytes, reply backchannels, ticket reuse and failures. Current durable packed messages remain capped at 512 bytes and Resources at one 74-part segment. Scheduled retry backoff, asynchronous outbound proof-of-work generation, propagation sync and live Python evidence remain. |
| Caller-polled stamp worker | IMPLEMENTED | Opaque job lifecycle incrementally prepares all 3000 HKDF rounds and searches candidates in caller-selected budgets capped at 64 work units per poll. Incremental SHA-256 prefix state replaces a materialized 768 KiB workblock. Progress exposes preparation rounds, attempts and terminal status; cancellation works during preparation and search. Deterministic tests compare one-unit and 64-unit schedules and validate results through the existing independent materialized-workblock validator. Router queue/progress integration, automatic peer-cost selection, durable resumable work and pinned Python/live evidence remain pending; callers must opt into this worker instead of the legacy blocking generator. |
| Peer and message persistence | IMPLEMENTED | Crash-recovering message journal and durable peer settings tests. The journal reads legacy put formats, compacts them into the current delivery-metadata format, and retains message status, signature, exact packed representation, delivery method/reason/attempt/progress/proof state across close/reopen and compaction. Outbound direct delivery transmits the exact signed representation retained by the queue, preserving title, fields, stamp and message ID instead of reconstructing a lossy message after restart. |
| Nomad conversations | WIP | Verified-peer opportunistic send and receive, persistent trust/pin/note and block-preference state, search, address entry, known-node inbox handoff, a UTF-8 aware composer, history and offline queue exist. Router receipt and signature events now update the live conversation state; successful inbound opportunistic packets emit proofs, and newly announced identities trigger revalidation of retained messages. The client is split into pure text/editor/state layers with curses confined to rendering, each unit tested. Enforced blocking, attachments, replies, reactions and non-opportunistic delivery remain. |
| Settings and self-announcement | WIP | The TUI has bounded, versioned, atomically replaced app settings for display name, enforced and advertised inbound stamp cost, announce-at-start, a minimum 30-minute periodic interval, propagation-node selection and manual announce. Announces use the core LXMF app-data encoder and runtime API, rotate/persist the delivery ratchet and sign its public key into the announce instead of constructing packets or cryptography in the app. Exact app-data, scheduling, corruption fallback, keyboard, dump and persistence tests exist. Propagation sync and upstream announce evidence remain; the UI labels non-operative preferences explicitly. |
| Network screen and active nodes | WIP | Configured TUI runtime consumes verified announces, associates Nomad nodes with LXMF inboxes, renders sorted persistent records, refreshes paths, and opens selected nodes through the live packet-backed browser with non-blocking loading, cancellation, reload and history states. The list scrolls around a selection held by destination so re-sorting cannot move the cursor, page-serving nodes are marked, and a details popup exposes per-node actions gated on what the announce supports. Resource page support, search, detailed diagnostics and upstream verification remain. |
| Native Micron browser | WIP | A caller-polled remote fetch state machine performs route discovery, authenticated link establishment, and packet- or resource-backed page retrieval. The bounded parser and curses renderer support sections, headings, latched emphasis and colours, alignment, dividers, links, and basic form-field display. Link navigation covers full destination URLs, same-node `:/page/...` links, relative paths and anchors in URL history. Tables and partials are detected but flattened; form editing/submission, in-page anchor positioning, caching and upstream page tests remain. |
| Channels/RRC, Interfaces, Config, Guide, Logs, hosted node | WIP | A bounded CBOR envelope codec parses and emits the integer-keyed NomadNet 1.2.0 RRC HELLO/WELCOME, join/part, message/notice, ping/pong, error and resource-envelope framing. Provenance-recorded fixtures execute pinned NomadNet's envelope helper and vendored CBOR codec for every type, optional fields, nested capabilities/limits, UTF-8, integer boundaries, resource metadata and unknown keys; the C test parses the Python bytes and reproduces each canonical known envelope. Unknown outer keys are skipped, not retained. Shell navigation seams exist. Live hub sessions, encrypted transport, room state/history and the remaining screens are not implemented. Settings is tracked separately above. |
| CLI utilities | WIP | `rnid`, `rnsd`, and `nomad-chat` history/node diagnostics exist, including JSON node output. Core utility parity remains. |
| Embedded portability | PLANNED | HAL boundary exists; cross-build examples and non-OpenSSL provider remain. |
| Upstream interoperability | BLOCKED | No complete bidirectional acceptance matrix or captured live upstream traffic yet. |

The compatibility revisions and update policy are recorded in `COMPATIBILITY.md`.
