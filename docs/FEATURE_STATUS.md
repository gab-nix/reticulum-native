# Canonical feature ledger

This is the source of truth for implementation progress. `IMPLEMENTED` means code and automated tests exist; `VERIFIED` additionally requires bidirectional upstream evidence. `WIP` names missing behavior, `PLANNED` has no complete implementation, and `BLOCKED` records an external dependency.

| Area | Status | Evidence and remaining work |
| --- | --- | --- |
| Complete inbound LXMF representation retention | IMPLEMENTED | Accepted verified messages now retain exact packed bytes just like unverified messages, rather than discarding title, arbitrary fields, attachments/media metadata and stamps after signature verification. `test_lxmf_router_stamps` checks verified opportunistic title, unknown extension and ticket stamp against decrypted bytes through compaction/reopen; `test_lxmf_router_direct` checks full verified 2 KiB Resource bytes, title, unknown fields and proof-of-work stamp. Signature and inbound-policy regressions cover known/unknown senders and unchanged size rejection. Strict Clang 64/64 and focused ASan/UBSan 4/4 pass. The existing 8 MiB packed bound, 16 MiB journal quota, 4 KiB content-preview admission limit and Resource segment limit remain; already discarded metadata cannot be recovered. Live upstream metadata verification remains pending. |
| Conversation preview ownership | IMPLEMENTED | The application cache bounds/copies text and never retains callback-scoped packed-message spans. Removing a rejected message rebinds relocated inline preview pointers, preserving subsequent text. `test_tui_state` exercises repeated rejection before distinct surviving messages. Full representations remain owned by the durable LXMF journal. |
| LXMF inbound block and size policy | IMPLEMENTED | The core router consults an application-owned source-block callback before history insertion, ticket learning, delivery callbacks or direct link packet proofs. Claimed sources are blocked even while identity verification is pending. Deferred policy rejection removes the retained item with `LXMF_ERR_BLOCKED`, never a false cryptographic signature-failure event. Accepting a source does not bypass stamp enforcement, matching the pinned LXMF ignored-source and stamp-policy distinction (`795fdaa2b0777c13033787d933d1afc94a2377cb`). A shared packed-message limit gates packet delivery, Resource advertisements and deferred validation. `test_lxmf_router_policy`, `test_lxmf_router_stamps` and C-to-C `test_lxmf_router_direct` cover blocked verified/unknown sources, changed policy, ticket suppression, stamp non-bypass, exact size boundaries, Resource rejection and withheld packet proof. Strict Clang 64/64 and focused ASan/UBSan 4/4 pass. Application preference binding and live Python exchanges remain; Resource completion proofs still acknowledge transport completion before application policy evaluation. |
| Propagation client session | WIP | Opaque caller-polled client verifies selected node identity/destination, discovers paths, establishes/identifies links, uploads proof-tracked Resources, lists bounded transient IDs, downloads in packet-safe batches, and acknowledges only application-confirmed durable messages. Matching hashes and duplicates are checked before callbacks; cancellation, per-operation deadlines, remote errors, retain-on-node and progress are exposed. `test_lxmf_propagation_session` covers local UDP multi-batch/resource-response sync, storage rejection, malformed IDs/content, access denial, upload, cancellation and timeout. Router/TUI integration, encryption/stamp preparation, durable replay/session state, resume, multi-segment transfer, retry and live Python evidence remain. See `PROPAGATION_CLIENT.md`. |
| Static hosted Nomad pages | IMPLEMENTED | Opaque opt-in POSIX service publishes explicitly selected `/page/` paths on an authenticated `nomadnetwork.node` destination, with binary packet/Resource responses, fresh bounded reads, explicit announces, global identification/allowlist policy and owned-link cleanup. `test_hosted_node` rejects traversal, hidden paths, symlinks, executable sources, unsupported `.allowed` sidecars and oversized files; `test_hosted_node_link` exercises C-to-C UDP identification denial, 2 KiB Resource and updated small packet pages. Local file-root reads exist, but remote file streaming metadata, executable pages, scans, sidecar policies, UTF-8 paths, multi-segment transfers and application/daemon controls remain WIP. See `docs/HOSTED_NODE.md`. No upstream network verification claimed. |
| Live short opportunistic UDP wire exchange | VERIFIED | `tools/test_lxmf_live_python.py` passes C → pinned Python `LXMRouter` and pinned Python `LXMessage.send()`/RNS UDP → C `receive-udp`, checking signatures, source/destination and exact synthetic content. `docs/LXMF_LIVE_OPPORTUNISTIC.json` records the 2026-09-03 run, exact RNS 1.5.2/LXMF 1.1.0 commits, declared native source commit, executable SHA-256, message IDs and payload hashes without plaintext/keys. This narrowly verifies identity-key short packets with preprovisioned public identities over loopback UDP, not announces, ratchets, stamps, receipts, router queues, links/resources, propagation, TCP or TUI delivery. See `docs/LXMF_LIVE_TESTING.md`; harness is opt-in and eight network-free safety tests cover pin enforcement, process cleanup and sanitizer diagnostics. |
| Propagation wire codecs | IMPLEMENTED | Allocation-free bounded codecs cover LXMF 1.1.0 seven-field propagation announces (unknown metadata/outer fields retained), uploads, `/get` list/download/acknowledgement requests, ID/message responses, integer errors and upload stamp rejection. Limits preserve decimal kilobytes, null differs from empty lists, transient IDs require 32 bytes, and opaque encrypted message bodies are not mistaken for validated LXMF. `test_lxmf_python_propagation` compares provenance-recorded synthetic fixtures generated by pinned upstream producers, exact byte re-encoding, truncation/mutation and bounds tests. This is offline codec evidence only, not bidirectional network verification. Propagation sessions, encryption/stamp handling, peering, upload/download scheduling, persistence and node hosting remain WIP. |
| C17 build, HAL, buffers, status API | IMPLEMENTED | Warning-as-error builds and unit tests. Embedded adapters remain planned. |
| Crypto, identities, destinations, packets | IMPLEMENTED | Known-answer and unit tests. Identity encryption supports announced X25519 ratchets, ordered private-ratchet decryption, ratchet IDs, identity-key fallback and strict ratchet enforcement. A bounded signed MessagePack ratchet store persists up to the upstream-default 512 private keys, rotates at the upstream-default 30-minute interval, rejects tampering and copies decryption keys newest-first. The runtime can sign the current ratchet into announces. The full upstream vector matrix remains WIP. |
| Signed announces and paths | WIP | Build/parse/verification, verified runtime callbacks and path snapshots tested. Verified events now expose the borrowed public ratchet bytes, and the bounded registry copies the ratchet plus decoded LXMF delivery name, stamp cost and compression capability while retaining original announce app data. Persistent discovery and upstream bidirectional capture remain. |
| UDP and TCP interfaces | IMPLEMENTED | Loopback tests, setup guide and a reachability-checked public uplink configuration. UDP receive tests use monotonic deadlines instead of scheduler-sensitive iteration budgets (`test_udp`, `test_udp_lxmf`). Protocol-level upstream testing remains. |
| AutoInterface, shared IPC, serial KISS, RNode | PLANNED | Framing primitives exist; interface drivers do not. |
| Transport forwarding | WIP | Basic ingress, forwarding and dedupe exist. Local ordinary-packet receipts now validate explicit or implicit identity proofs, report RTT/timeouts/cancellation, and can emit a proof on the receiving interface. Reverse-path forwarding, link/tunnel tables and persistent paths remain. |
| Links and channels | WIP | Handshake crypto, bounded channel state, and caller-polled outbound and inbound runtime link lifecycles exist. Identity-associated inbound destinations validate link requests, return signed LRPROOFs, authenticate RTT confirmation and encrypted packets, and use protocol-correct raw keepalives. Encrypted application packets support explicit ephemeral-key proofs, initiators can privately identify, and active links dispatch single-segment Resource control/data frames. Provenance-recorded pinned Python fixtures validate deterministic link-request/LRPROOF packet bytes, link IDs, proof and identification signing preimages, signatures, signalling, and RTT MessagePack plaintext; deterministic C-to-C UDP tests cover the runtime foundation. Random-IV ciphertext, live Python handshakes, backchannel routing and multi-hop reverse paths remain. |
| Requests and handlers | IMPLEMENTED | Authenticated inbound destinations register bounded opaque request handlers by the upstream SHA-256 path prefix with allow-none, allow-all, identified-peer and copied identity-allowlist policies. Valid request MessagePack reaches callback-scoped immutable views; arbitrary single-object responses are correlated to the received packet hash and sent as encrypted packets or single-segment Resources. C-to-C UDP tests cover identified access, packet response and 2 KiB Resource response; unit tests cover arbitrary response objects and malformed rejection. Deferred handlers, concurrent response Resources, multi-segment responses and pinned-upstream live exchanges remain. |
| Resources | WIP | The receive side parses advertisements, requests bounded windows, matches reordered parts by map hash, decompresses bz2, verifies hashes and emits completion proofs. A bounded single-segment sender constructs the pinned 11-field advertisement, optionally compresses, encrypts the complete stream, collision-checks part map hashes, serves requested parts and validates completion proofs. Runtime links expose caller-owned transfer state, bounded application acceptance/completion callbacks, encrypted advertisement/request/cancel/reject control frames, raw parts/proofs, progress, timeout and teardown handling. Deterministic C-to-C core and UDP runtime tests cover success, rejection, cancellation, malformed control frames, timeout and teardown. Transfers remain limited to the 74 parts carried in one advertisement; adaptive retries, hashmap updates, multi-segment transfer, resume and pinned-upstream evidence remain. |
| LXMF codec, signatures, stamps, tickets | WIP | Core codec and unit tests exist. Canonical pack/unpack uses bounded heap workspaces up to 8 MiB instead of the former hidden 4 KiB stack ceiling. Delivery announce parsing retains bounded unknown supported-function identifiers and extension MessagePack objects for lossless re-encoding; registry tests cover verified ratchet and advertised stamp/compression metadata retention. Provenance-recorded fixtures generated by pinned Python LXMF 1.1.0 validate delivery announce data plus exact signed message representations, IDs, signing preimages, UTF-8 title/content, renderer/reply/reaction and unknown fields, the 255-byte binary boundary, and destination-prefix-elided opportunistic payloads. A bounded, versioned, atomic ticket store issues, throttles, retains, expires and validates ticket-backed stamps using the pinned lifecycle constants. The router now parses bounded `FIELD_TICKET` values from verified messages, remembers valid unexpired tickets, and reuses them without dropping unknown fields. Random Reticulum ciphertext and live ticket exchanges remain unverified. |
| LXMF delivery and propagation | WIP | Opportunistic encoding matches the pinned Python layout and uses proof-backed delivery. Verified advertised ratchets are selected for opportunistic encryption, and the local signed history decrypts newest-first with bounded identity-key fallback. The Nomad client defaults to direct delivery: the router registers its authenticated inbound `lxmf.delivery` link destination, reuses active outbound links, sends packet-sized representations with ephemeral-key receipts, and sends larger retained representations through the bounded single-segment Resource runtime. Inbound packet and Resource representations share destination, message-ID, signature and duplicate validation. Router-owned link-packet proofs are returned only after signature, destination and configured stamp-policy acceptance; configured costs accept issued-ticket or proof-of-work stamps. Resource progress, proof hash, cancellation, rejection and timeout are durable; `SENT` is recorded only once transfer completion is proven, and the pinned direct-Resource COMPLETE callback maps to `DELIVERED`. C-to-C UDP tests exercise packet and Resource paths, exact retained bytes, reply backchannels, ticket reuse and failures. Durable packed storage and the canonical codec now support bounded representations up to 8 MiB, and the C-to-C Resource test transfers 2 KiB while preserving unknown fields. Content previews and the one 74-part Resource segment still limit practical end-to-end size. Scheduled retry backoff, app wiring for outbound stamp progress/cost resolution, propagation sync and live Python evidence remain. |
| Caller-polled stamp worker | IMPLEMENTED | Opaque job lifecycle incrementally prepares all 3000 HKDF rounds and searches candidates in caller-selected budgets capped at 64 work units per poll. Incremental SHA-256 prefix state replaces a materialized 768 KiB workblock. The router schedules one bounded job, prefers valid tickets, persists completed same-ID stamped representations, reports progress, and preserves explicit cancellation across restart. The Nomad client resolves costs only from verified LXMF delivery app-data and displays preparation or search progress. Deterministic tests cover schedules, validation, competition, changed costs, tickets, cancellation, recovery and verified-cost selection. Resumable unfinished work and pinned Python/live evidence remain. |
| Router outbound stamp queue | IMPLEMENTED | An optional verified peer-cost resolver selects bounded proof-of-work before any network attempt; valid unexpired tickets bypass work. One worker keeps messages QUEUED/STAMP, exposes rounds/attempts, handles changed costs, and does not consume network retry attempts. Completed stamps are re-signed and durably replaced under the unchanged ID, title, signature and unknown fields. Restart revalidates a retained stamp incrementally; unfinished hash work restarts. Cancellation survives journal reopen and suppresses automatic retries, while explicit send retries it. Tests `test_lxmf_router_stamp_queue` and `test_lxmf_router_stamps` cover work budgets, competition, disabled/invalid/changed costs, ticket bypass, orphan cleanup, transmitted stamps, same-ID replacement, torn replacement recovery, reopen and compaction. Strict Clang suite: 59/59; focused ASan/UBSan: 5/5. App resolver/progress wiring, resumable work, legacy content-only stamping, journal quota compaction and live Python proof-of-work exchanges remain. |
| Peer and message persistence | IMPLEMENTED | Crash-recovering message journal and durable peer settings tests. Version-4 put records retain exact opaque packed representations up to 8 MiB with 32-bit lengths; legacy v1/v2/v3 records migrate on compaction. Streaming writes and CRC scans use bounded small buffers, and a size-query API permits exact heap allocation for reads, router sending and deferred verification. Tests cover 65,537-byte and 8-MiB reopen/compaction round trips, legacy delivery metadata, malformed lengths, small read buffers and oversize rejection. Message status, signature, title/unknown fields, delivery method/reason/attempt/progress/proof state survive unchanged. The 16-MiB journal quota and 4-KiB content preview limit remain; storage capacity does not imply equivalent codec or network capacity. |
| Nomad conversations | WIP | Verified-peer messaging, persistent trust/pin/note and block-preference state, search, address entry, known-node inbox handoff, a UTF-8 aware composer, history and offline queue exist. Router receipt and signature events update live conversation state; the composer preserves pending queue reasons instead of calling asynchronous sends failed (`test_tui_settings_ui`). Inbound opportunistic packets emit proofs; valid identity announces trigger revalidation. Pure text/editor/state layers are separated from curses and unit tested. Enforced blocking, attachments, replies, reactions, propagation workflows and full direct-delivery upstream evidence remain. |
| Settings and self-announcement | WIP | The TUI has bounded, versioned, atomically replaced app settings for display name, enforced and advertised inbound stamp cost, announce-at-start, a minimum 30-minute periodic interval, propagation-node selection and manual announce. Announces use the core LXMF app-data encoder and runtime API, rotate/persist the delivery ratchet and sign its public key into the announce instead of constructing packets or cryptography in the app. Exact app-data, scheduling, corruption fallback, keyboard, dump and persistence tests exist. Propagation sync and upstream announce evidence remain. |
