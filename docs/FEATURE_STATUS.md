# Canonical feature ledger

This is the source of truth for implementation progress. `IMPLEMENTED` means code and automated tests exist; `VERIFIED` additionally requires bidirectional upstream evidence. `WIP` names missing behavior, `PLANNED` has no complete implementation, and `BLOCKED` records an external dependency.

| Area | Status | Evidence and remaining work |
| --- | --- | --- |
| C17 build, HAL, buffers, status API | IMPLEMENTED | Warning-as-error builds and unit tests. Embedded adapters remain planned. |
| Crypto, identities, destinations, packets | IMPLEMENTED | Known-answer and unit tests; full upstream vector matrix remains WIP. |
| Signed announces and paths | WIP | Build/parse/verification, verified runtime callbacks and path snapshots tested. Verified events now expose the borrowed public ratchet bytes, and the bounded registry copies the ratchet plus decoded LXMF delivery name, stamp cost and compression capability while retaining original announce app data. Persistent discovery and upstream bidirectional capture remain. |
| UDP and TCP interfaces | IMPLEMENTED | Loopback tests, setup guide and a reachability-checked public uplink configuration. Protocol-level upstream testing remains. |
| AutoInterface, shared IPC, serial KISS, RNode | PLANNED | Framing primitives exist; interface drivers do not. |
| Transport forwarding | WIP | Basic ingress, forwarding and dedupe exist. Local ordinary-packet receipts now validate explicit or implicit identity proofs, report RTT/timeouts/cancellation, and can emit a proof on the receiving interface. Reverse-path forwarding, link/tunnel tables and persistent paths remain. |
| Links and channels | WIP | Handshake crypto, bounded channel state, and caller-polled outbound and inbound runtime link lifecycles exist. Identity-associated inbound destinations validate link requests, return signed LRPROOFs, authenticate RTT confirmation and encrypted packets, and use protocol-correct raw keepalives. Encrypted application packets support explicit ephemeral-key proofs, and initiators can privately identify with a signed public identity over the active link. Deterministic C-to-C UDP tests cover this foundation. Inbound request handlers/resources, backchannel routing, multi-hop reverse paths and upstream link fixtures remain. |
| Resources | WIP | The receive side parses advertisements, requests bounded windows, matches reordered parts by map hash, decompresses bz2, verifies hashes and emits completion proofs. A bounded single-segment sender constructs the pinned 11-field advertisement, optionally compresses, encrypts the complete stream, collision-checks part map hashes, serves requested parts and validates completion proofs; a deterministic C-to-C core transfer test covers plain and response resources. Transfers remain limited to the 74 parts carried in one advertisement. Runtime sender scheduling, acceptance policy callbacks, retries, hashmap updates, multi-segment transfer, cancellation/resume and pinned-upstream evidence remain. |
| LXMF codec, signatures, stamps, tickets | WIP | Core codec and unit tests exist. Delivery announce parsing retains bounded unknown supported-function identifiers and extension MessagePack objects for lossless re-encoding; registry tests cover verified ratchet and advertised stamp/compression metadata retention. A provenance-recorded fixture generated by pinned Python LXMF 1.1.0 verifies C encode/decode behavior for delivery announce names, absent and boundary stamp costs, UTF-8 and compression advertisement. Live announce exchange, message representations, signatures and the full ticket lifecycle remain. |
| LXMF delivery and propagation | WIP | Opportunistic encoding matches the pinned Python layout and uses proof-backed delivery. The Nomad client defaults to direct delivery: the router registers its authenticated inbound `lxmf.delivery` link destination, reuses active outbound links, sends exact packed messages as encrypted link packets, proves them, and advances delivery only after an ephemeral link-key proof. After confirmation the initiator privately identifies, allowing the peer to index the authenticated link as a reply backchannel; C-to-C UDP tests exercise both directions. Unknown senders remain in a bounded durable unverified queue, verified announces retain ratchets/capabilities, and privacy-safe events expose queue reasons. Python message interoperability is not yet recorded. Large resource delivery, durable retry metadata, ratchet use/rotation, stamp policy and propagation sync remain. |
| Peer and message persistence | IMPLEMENTED | Crash-recovering message journal and durable peer settings tests. Outbound direct delivery now transmits the exact signed representation retained by the queue, preserving title, fields, stamp and message ID instead of reconstructing a lossy message after restart. |
| Nomad conversations | WIP | Verified-peer opportunistic send and receive, persistent trust/pin/note and block-preference state, search, address entry, known-node inbox handoff, a UTF-8 aware composer, history and offline queue exist. Router receipt and signature events now update the live conversation state; successful inbound opportunistic packets emit proofs, and newly announced identities trigger revalidation of retained messages. The client is split into pure text/editor/state layers with curses confined to rendering, each unit tested. Enforced blocking, attachments, replies, reactions and non-opportunistic delivery remain. |
| Settings and self-announcement | WIP | The TUI has bounded, versioned, atomically replaced app settings for display name, advertised inbound stamp cost, announce-at-start, a minimum 30-minute periodic interval, propagation-node selection and manual announce. Announces use the core LXMF app-data encoder and runtime API instead of constructing packets in the app. Exact app-data, scheduling, corruption fallback, keyboard, dump and persistence tests exist. Stamp enforcement, propagation sync, ratchet advertisement and upstream announce evidence remain; the UI labels non-operative preferences explicitly. |
| Network screen and active nodes | WIP | Configured TUI runtime consumes verified announces, associates Nomad nodes with LXMF inboxes, renders sorted persistent records, refreshes paths, and opens selected nodes through the live packet-backed browser with non-blocking loading, cancellation, reload and history states. The list scrolls around a selection held by destination so re-sorting cannot move the cursor, page-serving nodes are marked, and a details popup exposes per-node actions gated on what the announce supports. Resource page support, search, detailed diagnostics and upstream verification remain. |
| Native Micron browser | WIP | A caller-polled remote fetch state machine performs route discovery, authenticated link establishment, and packet- or resource-backed page retrieval. The bounded parser and curses renderer support sections, headings, latched emphasis and colours, alignment, dividers, links, and basic form-field display. Link navigation covers full destination URLs, same-node `:/page/...` links, relative paths and anchors in URL history. Tables and partials are detected but flattened; form editing/submission, in-page anchor positioning, caching and upstream page tests remain. |
| Channels/RRC, Interfaces, Config, Guide, Logs, hosted node | PLANNED | Shell navigation seams exist; working screens do not. Settings is tracked separately above. |
| CLI utilities | WIP | `rnid`, `rnsd`, and `nomad-chat` history/node diagnostics exist, including JSON node output. Core utility parity remains. |
| Embedded portability | PLANNED | HAL boundary exists; cross-build examples and non-OpenSSL provider remain. |
| Upstream interoperability | BLOCKED | No complete bidirectional acceptance matrix or captured live upstream traffic yet. |

The compatibility revisions and update policy are recorded in `COMPATIBILITY.md`.
